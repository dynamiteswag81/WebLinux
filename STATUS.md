## Design (details in code comments)
**Kernel:**
- !MMU, single CPU.
- Every task is a Web Worker running its own kernel instance on one shared memory.
- Context switches pass a baton with atomic notify/wait.
- `current` lives in TLS.

**Interrupts:** a bitmask, `wasm_irq_pending`, set by the host. The kernel services it whenever interrupts get re-enabled, or from the idle loop.

**User programs:** PIE wasm modules loaded by `binfmt_wasm`. They import `linux.syscall`, which is the kernel's export.

**vfork:** a libc macro (setjmp + the `wasm_vfork` syscall). The child borrows the parent's worker. The parent resumes when JS throws the `__c_longjmp` tag.

**fork():**
- Programs linked with `WASM_FORK=1` get Asyncify.
- The JS `linux.fork` import unwinds the stack, saves it along with the shadow stack pointer, then calls `wasm_vfork` with flag 1.
- The kernel snapshots the process's memory (`arch/wasm/kernel/fork.c`).
- The child replays the saved stack and gets 0. When it execs or exits, the kernel restores the parent's memory and JS replays the stack with the child's PID.
- Tested: true fork semantics. The child can return from the function that called fork, and memory is isolated.

**Signals:** the kernel fills a mailbox that libc registered, and the libc syscall wrapper runs the handlers.

**main:** `crt1` handles `main(void)`, `main(argc, argv)` and `main(argc, argv, envp)`, via weak symbols plus GOT/null imports in `kworker`.

NetSurf 3.11 (`build/build-netsurf.sh`, all from Ubuntu's source pool via fetch-sources.sh):

Drivers (`linux/arch/wasm/drivers/`, host side in `public/js/`):
- `wasmfb.c` / `screen.js`: XRGB8888 frame buffer in kernel memory, blitted every animation
  frame; `?mode=WxH` (kernel `wasmfb.mode=`). fbcon + VT on it.
- `wasminput.c` / `screen.js` + `keymap.js`: keyboard (KeyboardEvent.code -> keycode, Shift
  synthesized for synthetic events) and absolute pointer + wheel; ring of 12-byte events.
- `wasmnet.c` / `net.js` + `host/netrelay.js`: eth0 via tx/rx rings; JS NAT router
  (10.0.2.15 guest, 10.0.2.2 gateway = the page server's machine, 10.0.2.3 DNS); every TCP
  connection / UDP flow is one WebSocket to `server.js`'s relay, which opens the real socket.
- `wasmsnd.c` / `audio.js` + `audio-worklet.js`: ALSA playback (S16_LE, 1-2 ch, 8-48 kHz);
  the worklet reads the ring from shared memory, raises WASM_IRQ_SOUND per period.
- entropy: `host.get_random` seeds the CRNG at boot.
- `wasmblk.c` / `disk.js`: /dev/wda, one request at a time via a shared slot; the disk worker
  uses an OPFS sync access handle (`disk0.img`, 256 MiB default), falls back to memory.
  `?disk=opfs|mem|none`, `?disksize=MiB`. Init formats a blank disk with mke2fs, mounts it
  (ext4 driver) and switches to an overlay root; `weblinux.volatile` on the cmdline skips it.

Notes:
- bash: `PGRP_PIPE` must stay off (build-bash.sh undefines it): with it, a job's first
  child blocks on a pipe until the parent runs, but our fork() runs the child until it execs.
- wasm-cc passes `-u __main_argc_argv`: crt1 references main weakly, so a main inside an
  archive (BusyBox's libbb) was not linked.
- BusyBox: SHA1/SHA256_HWACCEL off (x86 asm); musl's empty libm.a etc. are created by build-libc.sh.
- Kernel patches: export only the new commit, e.g.
  `git -C linux format-patch --start-number 7 -o ../patches/linux HEAD~1`, so old patch files
  don't churn.
